Kapitel 01

Systemübersicht & Technische Architektur

CRM Beratung ist eine lokal betreibbare, offline-fähige Komplettlösung für Beratungsunternehmen, Kanzleien und Agenturen. Sie trennt strikt zwischen dem Administrator-Leitstand (11 Arbeitsbereiche) und dem Mandantenportal (9 kundenbezogene Ansichten) und speichert sämtliche Daten transaktional auf dem eigenen Server in einer relationalen SQLite-Datenbank.

🖥️ Frontend-Schicht

React 19 Single-Page-Application (TypeScript) mit Tailwind CSS v4, Recharts-Diagrammen und Lucide-Icons.

⚙️ Backend-Schicht

Express-Server (server.ts) auf Port 3000 mit JSON-REST-APIs (50 MB Payload-Limit für Dokumente).

🗄️ Persistenz-Schicht

Native Node.js SQLite-Datenbank (node:sqlite) im WAL-Modus unter /data/crm.db plus Browser-Offline-Cache.

Kapitel 02

Schritt-für-Schritt-Installationsanleitung

⚠️ Wichtige Voraussetzung: Node.js ≥ 22.5.0 Dieses System nutzt das in Node.js eingebaute Modul node:sqlite (DatabaseSync). Installieren Sie daher zwingend Node.js Version 22 LTS (oder neuer). Ältere Versionen wie Node 18 oder 20 starten den Server nicht.

Systemvoraussetzungen

  • Node.js: Version 22.5.0 oder höher (empfohlen: v22.x LTS)
  • Paketmanager: npm (im Lieferumfang von Node.js enthalten)
  • Freier Netzwerkport: TCP-Port 3000
  • Schreibrechte: Schreibzugriff im Projektordner für das Unterverzeichnis ./data

Installation & Start (Entwicklung & Test)

  1. Node.js-Version überprüfen

    Öffnen Sie ein Terminal und verifizieren Sie die installierte Node-Version:

    node -v
npm -v
  2. Projektverzeichnis vorbereiten

    Klonen Sie das Repository oder entpacken Sie das Archiv und wechseln Sie in das Verzeichnis:

    git clone <REPOSITORY-URL> crm-beratung
cd crm-beratung
  3. Abhängigkeiten installieren

    Installieren Sie alle Frontend- und Backend-Pakete über npm:

    npm install
  4. Umgebungsvariablen einrichten (optional)

    Erstellen Sie bei Bedarf eine .env-Datei aus der Vorlage. Für den Standard-CRM-Betrieb mit SQLite sind keine externen Keys nötig:

    cp .env.example .env
  5. Entwicklungsserver starten

    Startet Express + Vite auf Port 3000 und initialisiert automatisch ./data/crm.db:

    npm run dev

    Öffnen Sie anschließend http://localhost:3000 im Browser. Dieses HTML-Handbuch ist zusätzlich unter http://localhost:3000/handbuch.html abrufbar.

Produktions-Deployment (Live-Betrieb)

Für den stabilen Produktivbetrieb werden Frontend und Backend in das Verzeichnis dist/ kompiliert:

# 1. TypeScript prüfen
npm run lint

# 2. Frontend & Server-Bundle bauen
npm run build

# 3. Produktiv-Server starten
NODE_ENV=production npm start

Dauerbetrieb mit PM2 & Reverse Proxy (Empfehlung)

npm install -g pm2
NODE_ENV=production pm2 start dist/server.cjs --name crm-beratung
pm2 startup
pm2 save

Betreiben Sie das Portal hinter einem Reverse Proxy (z. B. Nginx oder Caddy) mit HTTPS/TLS und leiten Sie den Traffic auf http://127.0.0.1:3000 weiter. Sichern Sie den Ordner ./data/ regelmäßig in Ihre Server-Backups.

Kapitel 03

Anmeldung, Rollenmodell & Sicherheitsarchitektur

Standard-Zugangsdaten bei Ersteinrichtung

Rolle Login-Reiter Benutzername Passwort Hinweis
Administrator Admin (CRM-Leitung) admin admin123 Unbedingt direkt nach Erstanmeldung ändern!
Mandant (Stammkunde) Mandant (Kundenportal) max.muster kunde123 Max Mustermann (Muster GmbH)
Mandant (Neukunde) Mandant (Kundenportal) anna.schmidt kunde123 Anna Schmidt (Schmidt AG)

Selbstregistrierung & Passwort-Generator

Unter dem Reiter Mandant (Kundenportal) führt der Link „Noch kein Mandantenkonto? Jetzt registrieren“ zum Registrierungsformular. Dieses bietet:

  • Echtzeit-Passwort-Checkliste: Prüft Mindestlänge (8 Zeichen), Groß-/Kleinbuchstaben, Ziffern und Sonderzeichen.
  • Integrierter Passwort-Generator: Erzeugt mit einem Klick ein 15-stelliges Zufallspasswort (Sonderzeichen individuell abwählbar).
  • Admin-Freigabepflicht: Jedes neu registrierte Konto wird mit approved: false angelegt und kann sich erst einloggen, nachdem der Administrator es in der Kundenverwaltung freigeschaltet hat.

Eingebaute Schutzmechanismen

🔒 Brute-Force-Sperre

Nach 5 fehlerhaften Anmeldeversuchen wird das Login-Formular automatisch für 30 Sekunden gesperrt. Jeder Fehlversuch und jede Sperre wird im Audit-Log protokolliert.

⏱️ Inaktivitäts-Wächter (15 Minuten)

Erfolgt 15 Minuten lang keine Maus- oder Tastaturaktivität, meldet sich das Portal automatisch ab. 60 Sekunden vor Ablauf erscheint ein Countdown-Dialog zur 1-Klick-Verlängerung.

🔏 SHA-256 Passwort-Hashing

Passwörter werden clientseitig via SHA-256 gehasht (inkl. reinem JS-Fallback für lokale HTTP-Umgebungen), bevor sie gespeichert oder abgeglichen werden.

🎹 Globale Tastaturkürzel

Strg + D / Cmd + D wechselt direkt zum Dashboard. Strg + K / Cmd + K springt direkt in die Kunden- bzw. Produktsuche.

Kapitel 04

Admin: Management Dashboard & Kennzahlen

Das Management Dashboard bildet die zentrale Kommandozentrale der Kanzlei- oder Unternehmensleitung. Über die obere Tab-Leiste lässt sich direkt zwischen Übersicht und Benutzer-Aktionen umschalten.

Infokarten & Analysen auf dem Dashboard

  • Mandanten- & Neuanmeldungs-Übersicht: Zeigt aktive Kunden, neu registrierte bzw. freizuschaltende Mandanten („Neuanmeldungen“) sowie Umsatz- und Projektkennzahlen.
  • Dokumenten-Speicherverbrauch: Visualisiert die Gesamtgröße und Anzahl aller in der Dokumenten-Zentrale abgelegten Verträge, PDFs und Mediendateien.
  • 24h-Login-Sicherheitsmonitor: Flächendiagramm (Recharts) über fehlgeschlagene Login-Versuche der letzten 24 Stunden mit automatischer Bedrohungsstufe (Sicher / Warnung / Kritisch) sowie einem Simulator („Fehler simulieren“) zum Testen der Alarmierung.
  • Online/Offline-Sync-Steuerung: Erlaubt das bewusste Pausieren oder Reaktivieren der Server-Synchronisation.
  • Integritätsprüfung: Validiert per Klick alle relationalen Verknüpfungen zwischen Kunden, Dateien, Rechnungen, Terminen und Nachrichten.
  • SQLite-Datenbankverwaltung: Direkter Zugriff auf Tabellenstatistiken, manuelles Speichern/Neuladen sowie Export (.db / .json / E2EE-Backup) und Import.
Kapitel 05

Admin: Benutzer-Aktionen & Chronologisches Audit-Log

Der dedizierte Navigationspunkt Benutzer-Aktionen (sowie der Reiter im Dashboard-Kopf) liefert eine lückenlose, chronologische Übersicht aller im System protokollierten Vorgänge auf Basis der AuditLogs.

📊 4 KPI-Zusammenfassungskarten

Zeigen auf einen Blick: Protokollierte Aktionen (inkl. aktiver Initiatoren), Erfolgreiche Aktionen, Hinweise & Warnungen sowie Fehler & Sperren.

🕒 Zwei Ansichtsmodi

Wechseln Sie jederzeit zwischen der nach Kalendertagen (Heute, Gestern, Datum) gruppierten Chronologischen Zeitleiste und der kompakten Tabellenansicht.

Filter-, Sortier- & Exportfunktionen

  • Status-Filter: Segmentierte Schnellauswahl für Alle, Erfolg, Info, Warnung und Fehler.
  • Benutzer-/Initiator-Filter: Dropdown über alle im Log vorkommenden Benutzerkonten (z. B. admin, max.muster).
  • Volltextsuche: Durchsucht Aktionstitel, Auslöser, Detailbeschreibung und IP-Adresse.
  • Chronologische Reihenfolge: Umschaltbar zwischen Neueste zuerst und Älteste zuerst.
  • Export & Bereinigung: „Log exportieren (CSV)“ lädt die Audit-Historie zur Archivierung herunter; „Protokoll leeren“ setzt die Log-Liste nach Rückfrage zurück.
Kapitel 06

Admin: Kundenverwaltung, Filter & CSV/JSON-Sicherung

In der Kundenverwaltung pflegen Sie sämtliche Stammdaten, Zugangsdaten und Berechtigungen Ihrer Mandanten.

  • Mandanten anlegen & bearbeiten: Erfassen von Name, Unternehmen, E-Mail, Telefon, Adresse, Status (Neukunde, Aktiv, Stammkunde, Inaktiv), individuellen Notizen, CRM-Titel und Landingpage-URL.
  • Freischaltungs-Workflow: Neu selbstregistrierte Mandanten erscheinen prominent mit Freischalten-Aktion. Erst nach Freigabe ist ein Login möglich.
  • Filterung & Sortierung: Kombinierbare Filter nach Status (z. B. Neukunde, Aktiv) sowie Sortierung nach Registrierungsdatum (neueste/älteste zuerst) oder Name.
  • Passwort zurücksetzen: Administratoren können direkt im Bearbeitungsdialog ein neues Passwort vergeben.
  • Lokale Sicherung & Import: Mit den Buttons CSV Export und JSON Export laden Sie die vollständige Kundenliste zur lokalen Sicherung herunter. Über CSV Import / JSON Import lassen sich Kundenlisten wieder einspielen (bestehende IDs werden aktualisiert, neue ergänzt).
Kapitel 07

Admin: Kunden-Projekte, Fahrplan-Schablonen & Übergabeprotokoll

Das Modul Kunden-Projekte steuert den Beratungs- und Umsetzungsfortschritt jedes einzelnen Mandanten.

  • 5-Phasen-Fahrplan (Roadmap): Jeder Mandant durchläuft bis zu 5 definierte Phasen mit einzelnen To-dos (Verantwortlichkeit: Admin, Kunde oder Beide). Nur der Administrator hakt erledigte Aufgaben ab und schaltet die nächste Phase frei.
  • Roadmap pro Kunde aktivieren/deaktivieren: Lässt sich für jeden Mandanten einzeln ein- oder ausschalten.
  • Schablonen-Builder (Roadmap-Templates): Erstellen und bearbeiten Sie wiederverwendbare Branchen- oder Beratungs-Vorlagen (inkl. Phasen und Aufgaben) und weisen Sie diese neuen oder bestehenden Mandanten per Klick zu.
  • Onboarding & Übergabeprotokoll: Einsehen der vom Kunden ausgefüllten Unternehmensdaten (Branche, Zielgruppe, Produkte, Sonderwünsche) sowie Dokumentation des technischen Rollouts (Landingpage aktiv, CRM aktiv, Benutzer-DB aktiv, Zugangsdaten, Kundenbestätigung).
Kapitel 08

Admin: Warenwirtschaftssystem (WWS)

Das integrierte Warenwirtschaftssystem (WWS) verwaltet Produkte, Lagerbestände, Bewegungen und Lieferantenbestellungen direkt im CRM:

📦 Artikelstamm & Mindestbestände

Verwaltung von Artikelnummer (SKU), Kategorie, Lagerort, aktuellem Bestand, Mindestbestand (automatische Warnung bei Unterschreitung), Einkaufs- und Verkaufspreis.

🔄 Lagerbewegungen & Lieferanten

Nachvollziehbare Ein- und Ausbuchungen (Wareneingang, Warenausgang, Korrektur) mit Begründung und Bearbeiter sowie Lieferantenverwaltung inkl. Bestellstatus (Entwurf, Bestellt, Geliefert).

Kapitel 09

Admin: Dokumenten-Zentrale, Direktnachrichten (DMs) & Termine

Dokumenten-Zentrale & DGM-Signaturprüfung

  • Kategorisierte Ablage nach Vertrag, Video, Dokument und Marketing mit Mandantenzuordnung.
  • Statusworkflow pro Datei: Ausstehend, Geprüft, Signiert.
  • Revisionssichere Signaturansicht: Bei digital signierten Dokumenten (DGM) wird die erfasste Unterschrift zusammen mit dem HMAC-SHA256-Hash und dem Zeitstempel angezeigt.

Direktnachrichten (DMs) & E2EE

  • Echtzeit-Synchronisation aller Chats mit den Mandanten inkl. Zähler ungelesener Nachrichten in der Sidebar.
  • Unterstützung für Dateianhänge sowie optionale symmetrische Ende-zu-Ende-Verschlüsselung.

Termine & Planung

  • Erstellen und Verwalten von Beratungs- und Projektsitzungen (Titel, Datum, Uhrzeit, Beschreibung, zugeordneter Mandant, Status Geplant / Abgeschlossen / Abgesagt).
Kapitel 10

Admin: Finanzen, Rechnungen & KI-Bot Training

Finanzen & Rechnungen

  • Rechnungsgenerator: Anlegen von Rechnungen mit Rechnungsnummer, Fälligkeitsdatum, mehreren Einzelpositionen und Beschreibung.
  • Steuerlogik: Unterstützt reguläre 19 % USt. sowie steuerfreie Vermittlungen (0 % gemäß § 4 Nr. 11 UStG) mit automatischer Berechnung von Netto, Steuerbetrag und Brutto.
  • Zahlungsstatus & Steuerbüro-Export: Verfolgen von Bezahlt, Offen und Überfällig sowie 1-Klick-Export als steuerberaterkonforme CSV-Datei.

KI-Bot Training (Lokale NLP-Engine)

  • Arbeitet vollständig lokal ohne externe Cloud-API-Kosten auf Basis von Keyword-Triggern.
  • Regeln pflegen: Kommagetrennte Schlüsselwörter definieren und eine passende Antwort hinterlegen (inkl. Verwendungszähler).
  • Unresolved Queries: Erkennt der Bot eine Kundenfrage nicht, landet diese automatisch in der Liste der offenen Rückfragen. Der Administrator kann daraus direkt eine neue Bot-Regel anlernen.

Kapitel 12

SQLite-Datenbank, Synchronisation & Datensicherung

Alle CRM-Daten werden serverseitig in einer echten relationalen SQLite-Datenbank unter /data/crm.db gespeichert. Die Datenbank arbeitet im performanten WAL-Modus (Write-Ahead Logging) und wird beim Start automatisch initialisiert.

Tabellenstruktur in /data/crm.db (15 Tabellen)

System & Konten

app_state, admin_profile, customers, audit_logs

Projekte & Kommunikation

files, messages, appointments, custom_templates

Finanzen, WWS & Bot

invoices, inventory_products, suppliers, stock_movements, supplier_orders, bot_rules, unresolved_queries

Vier Wege der Datensicherung & Wiederherstellung

  1. SQLite-Datenbankdatei (.db) herunterladen & einspielen: Über das SQLite-Panel im Admin-Dashboard wird die komplette Datei crm_datenbank_YYYY-MM-DD.db exportiert bzw. per Upload wiederhergestellt.
  2. SQLite-Stand als JSON herunterladen: Exportiert den Live-Bestand aus /data/crm.db direkt als formatierte Datei crm_sqlite_backup_YYYY-MM-DD.json.
  3. E2EE-verschlüsseltes JSON-Backup: Verschlüsselt die Daten vor dem Download mit einer selbst gewählten Passphrase (SHA-256 Stream-Cipher) zur sicheren externen Ablage.
  4. Dateisystem-Backup auf dem Server: Stoppen Sie bei Bedarf den Server kurz oder sichern Sie die SQLite-Datei konsistent auf Serverebene (inkl. crm.db-wal / crm.db-shm, falls vorhanden).
ℹ️ Automatische Migration von crm_data.json Erkennt der Server beim ersten Start eine vorhandene Legacy-Datei ./data/crm_data.json, übernimmt er deren Inhalte automatisch in die neuen SQLite-Tabellen, bevor der reguläre Betrieb startet.
Kapitel 13

REST-API-Referenz & Fehlerbehebung

Server-Endpunkte (Port 3000)

Methode Endpunkt Beschreibung
GET /api/crm-data Liefert das gesamte CRMData-Objekt aus SQLite
POST /api/crm-data Schreibt den gesamten CRMData-Zustand transaktional in SQLite und liefert aktuelle Statistiken zurück
GET /api/sqlite/status Gibt Dateigröße, Pfad, Journal-Modus, Zeitstempel und Datensatzzahlen je Tabelle zurück
GET /api/sqlite/download Sendet die vollständige binäre SQLite-Datei als Download (.db)
GET /api/sqlite/export-json Exportiert den aktuellen SQLite-Datenstand als formatierte JSON-Datei
POST /api/sqlite/import-db Validiert und importiert eine Base64-kodierte .db-Datei in /data/crm.db
GET/POST /api/sqlite/settings/:key Liest oder speichert Konfigurationswerte in der Tabelle app_state
GET /handbuch.html Stellt dieses vollständige HTML-Handbuch direkt über den Webserver bereit

Häufige Fragen & Troubleshooting

Problem Mögliche Ursache Lösung
Server startet nicht (Cannot find module 'node:sqlite') Installierte Node.js-Version ist älter als v22.5.0. Aktualisieren Sie auf Node.js 22 LTS (z. B. via nvm install 22 && nvm use 22) und starten Sie erneut.
Sidebar zeigt Sync-Fehler Backend nicht erreichbar, Offline-Modus aktiv oder Schreibrechte auf ./data fehlen. Prüfen Sie den Server-Prozess, den Online-Schalter im Dashboard sowie die Dateiberechtigungen von ./data/crm.db.
Neu registrierter Kunde kann sich nicht anmelden Konto wartet noch auf administrative Freigabe. Melden Sie sich als Admin an und schalten Sie den Mandanten in der Kundenverwaltung frei.
Anmeldung nach 5 Fehlversuchen blockiert Automatischer Brute-Force-Schutz hat ausgelöst. Warten Sie den 30-Sekunden-Countdown ab; anschließend ist das Eingabefeld automatisch wieder entsperrt.
Offline-Nutzung im iFrame eingeschränkt Strikte Browser-Cookie-/Storage-Richtlinien in eingebetteten Frames. Öffnen Sie die Anwendung direkt in einem eigenen Browser-Tab unter http://localhost:3000.
